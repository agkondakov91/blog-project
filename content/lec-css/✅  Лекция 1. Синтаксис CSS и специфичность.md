## ==Цели занятия==

До сих пор мы строили структуру страниц, опираясь только на разметку и html-теги. Мы строили визитку, галерею, FAQ-аккордеон, лендинг. Всё это уже работает и логично размечено, но выглядит как черновик: браузерный шрифт, чёрный текст на белом фоне, никакого визуального ритма.

> [!tip]
Сегодня мы начинаем **стилизовать** то, что уже построено. 

Вы научитесь:

- **подключать** CSS к HTML-странице,
- **писать** правило по схеме «селектор → свойство → значение»,
- **выбирать** элементы для стилизации разными способами,
- **предсказывать**, какое правило победит, если два стиля конфликтуют.

Последний пункт — самый важный. Это тема, где новички обычно начинают судорожно расставлять **`!important`**, вместо того чтобы понимать, _почему_ браузер выбрал именно этот стиль. Сегодня мы во всём разберёмся, и сделаем так, чтобы `!important` вам не понадобился.

## ==Введение==

🔖 [Стартовый репозиторий курса](https://github.com/hexlet-education-track/css-portfolio-project)

Если <font color="#ff0000">HTML</font> отвечает на вопрос «**что это?**» — заголовок, список, картинка, то <font color="#ff0000">CSS</font> отвечает на другой вопрос — «**как это должно выглядеть?**».

Представьте, что HTML — это здание из кирпичей: стены на месте, комнаты подписаны, всё стоит и не падает. А CSS — это дизайнер интерьера, который приходит и решает: какого цвета будут стены, какой формы будут окна, где повесить шторы.

> [!tip] Важно
>  HTML и CSS это **два разных языка с разными задачами**. Не пытайтесь через HTML-теги решать вопросы внешнего вида (как раньше делали через `<font color="red">`) — для этого целиком существует CSS.

## ==Часть 1. Как подключить CSS к странице==

🔖 [Как подключить CSS к HTML](https://thecode.media/kak-podklyuchit-css-k-html/)

Есть три способа связать CSS с HTML — но реально используется в основном один.

### <mark style="background:rgba(240, 200, 0, 0.2)">Внешний файл (external) — основной способ</mark>

Стили выносятся в отдельный файл `style.css` и подключаются через тег `<link>` внутри `<head>` в файле HTML:

```html
<head>
  <link rel="stylesheet" href="style.css">
</head>
```

```css
/* style.css */
body {
  color: #333;
}
```

> [!warning] Почему именно так 
> Один файл `style.css` можно подключить к десяткам HTML-страниц сразу. Поменяли цвет фона в одном месте — обновились все страницы сайта. 

Это и есть главная сила CSS: <font color="#ff0000"><b>разделение структуры и оформления</b></font>.

### <mark style="background:rgba(240, 200, 0, 0.2)">Внутренний блок (internal)</mark>

Можно писать стили прямо в `<head>` внутри тега `<style>`:

```html
<head>
  <style>
    body {
      color: #333;
    }
  </style>
</head>
```

> [!info]
Работает только для одной этой страницы — в других HTML-файлах эти стили не появятся.

### <mark style="background:rgba(240, 200, 0, 0.2)">Инлайн-стиль (inline)</mark>

Стиль пишется прямо в атрибуте `style` у конкретного тега:

```html
<p style="color: #333;">Текст</p>
```

> [!warning] Инлайн-стили — почти всегда плохая идея 
> Они смешивают структуру и оформление обратно в одном месте — то, от чего мы уходили. Кроме того, как вы увидите дальше, инлайн-стиль обладает огромной специфичностью и перебивает почти всё остальное, а это усложняет отладку. 

Используйте их только в исключительных случаях (например, стиль генерируется на лету через JavaScript).

**В курсе мы работаем только с внешним файлом** — заведите `style.css` рядом с вашими HTML-файлами прямо сейчас.

## ==Часть 2. Анатомия CSS-правила==

🔖 [Основы CSS](https://developer.mozilla.org/ru/docs/Learn_web_development/Getting_started/Your_first_website/Styling_the_content)

CSS состоит из правил, которые указывают браузеру, как стилизовать элементы. Каждое правило — это инструкция, например: «***Сделайте все заголовки синими***».

Любое CSS-правило состоит из трёх частей:

```css
selector {
  property: value;
}
```

- **селектор** — _к кому_ обращаемся (какой элемент стилизуем),
- **свойство** — _что именно_ меняем (цвет, размер, отступ...),
- **значение** — _каким_ делаем это свойство.

```css
p {
  color: red;
  font-size: 18px;
}
```

Здесь мы говорим браузеру: «у всех `<p>` на странице сделай текст красным, а размер шрифта — 18 пикселей».

> [!tip] Читайте CSS-правило как предложение
> «Для параграфа: цвет — navy; размер шрифта — 18 пикселей». Если вы можете так прочитать код вслух — вы его понимаете.

<font color="#ff0000"><b>Какие свойства можно стилизовать у элемента?</b></font>

Свойст, которые можно стилизовать, достаточно много. Не нужно сразу их все запоминать. Мы будем сталкиваться с основными свойствами по ходу курса, а некоторые будем искать в документации. 

Однако, для саморазвития, полезно посмотреть с чем вам придётся работать в будущем.

🔖 https://developer.mozilla.org/ru/docs/Web/CSS/Reference

## ==Часть 3. Селекторы: как выбрать нужный элемент==

🔖 [CSS Diner - игра для изучения CSS](https://flukeout.github.io/)

Для того, чтобы можно было выбрать любой **html-элемент** на странице в CSS предусмотрены селекторы. Посмотрим на базовые селекторы.

### <mark style="background:rgba(240, 200, 0, 0.2)">Базовые селекторы</mark>

|Селектор|Что выбирает|Пример|
|---|---|---|
|Тег|Все элементы этого тега|`p { }` — все параграфы|
|Класс|Элементы с этим классом|`.card { }` — все с `class="card"`|
|ID|Один конкретный элемент|`#header { }` — элемент с `id="header"`|
|Универсальный|Вообще всё на странице|`* { }`|
Например, у нас есть такая разметка:

```html
<p class="intro">Привет!</p>
<div id="main-header">Заголовок</div>
```

```css
p { color: gray; }
.intro { font-weight: bold; }
#main-header { background: navy; }
```

> [!info] Класс vs ID
> Класс (`.intro`) можно вешать на сколько угодно элементов — это как бейджик «я такой-то». ID (`#main-header`) должен быть **уникальным** на странице — как паспорт, только один владелец.

Если вы стилизуете группу похожих элементов (карточки товаров, кнопки) — почти всегда нужен класс, а не ID.

### <mark style="background:rgba(240, 200, 0, 0.2)">Комбинированные селекторы</mark>

Селекторы можно сочетать, чтобы точнее указать, что необходимо стилизовать:

```css
/* Все ссылки внутри nav */
nav a { color: white; }

/* Прямые дети main (не внуки) */
main > section { margin-bottom: 20px; }

/* Элемент сразу после header */
header + main { padding-top: 40px; }

/* Несколько классов через запятую — общее правило сразу для всех */
h1, h2, h3 { font-family: sans-serif; }
```

- `nav a` — пробел означает «где угодно внутри», на любой глубине вложенности;
- `main > section` — знак `>` означает «только прямой ребёнок», не дочерний;
- `header + main` — знак `+` означает «сосед сразу после».

### <mark style="background:rgba(240, 200, 0, 0.2)">Псевдоклассы: состояния элемента</mark>

Псевдокласс описывает **состояние** элемента, а не его тип или класс:

```css
a:hover { color: red; }        /* при наведении курсора */
input:focus { border-color: blue; }  /* когда поле в фокусе */
li:first-child { font-weight: bold; } /* первый элемент в списке */
```

Мы вернёмся к псевдоклассам подробнее, когда дойдём до интерактивных элементов — а пока достаточно знать, что двоеточие `:` в селекторе значит «в каком-то состоянии», а не «часть имени».

## ==Часть 4. Специфичность: кто победит при конфликте==

🔖 [CSS Специфичность](https://developer.mozilla.org/ru/docs/Web/CSS/Guides/Cascade/Specificity)

Что если два правила указывают на один и тот же элемент, но с разными значениями? Например, у нас есть такая разметка **html**:

```html
<p class="intro">Какого цвета будет этот текст?</p>
```

В **css**, при этом, указаны такие стили:

```css
p { color: blue; }
.intro { color: green; }
```

> [!warning] Вопрос
> Какой цвет в итоге применится к элементу?

Ответ: **зелёный**. Не потому что `.intro` написан позже в файле, а потому что у **класса приоритет выше**, чем у тега. Это и есть специфичность — система баллов, по которой браузер решает, чьё правило важнее.

### <mark style="background:rgba(240, 200, 0, 0.2)">Как считаются баллы</mark>

Специфичность выражается в виде четырёх чисел (0, 0, 0, 0), где каждое соответствует определённому типу селектора:

| Тип селектора               | Баллы                                          | Пример               |
| --------------------------- | ---------------------------------------------- | -------------------- |
| Инлайн-стиль                | 1, 0, 0, 0 = <font color="#ff0000">1000</font> | `style="color: red"` |
| ID                          | 0, 1, 0, 0 = <font color="#ff0000">100</font>  | `#header`            |
| Класс, псевдокласс, атрибут | 0, 0, 1, 0 = <font color="#ff0000">10</font>   | `.card`, `:hover`    |
| Тег                         | 0, 0, 0, 1 = <font color="#ff0000">1</font>    | `p`, `div`           |
Баллы за все части селектора **складываются**. Например, `nav .active a` — это класс (10) + тег (1) = **11 баллов**.

> [!warning] Частая ошибка
> Думать, что побеждает правило, которое ниже в файле. Порядок в файле решает **только при равной специфичности**. Если у одного правила 10 баллов, а у другого 1 — выиграет то, что с 10 баллами, даже если оно написано раньше.

### <mark style="background:rgba(240, 200, 0, 0.2)">А если специфичность одинаковая?</mark>

Вот тут действительно работает порядок в файле — побеждает то правило, которое **написано ниже**:

```css
.button { background: gray; }
.button { background: navy; } /* это правило победит — оно ниже */
```

### <mark style="background:rgba(240, 200, 0, 0.2)">Почему !important — это не решение, а побег от проблемы</mark>

```css
p { color: blue !important; }
```

`!important` перебивает вообще всё, кроме другого `!important` с ещё бо́льшим приоритетом. Звучит как удобная кнопка «сделать по-моему», но у неё есть цена:

> [!warning] Проблема !important 
> Как только вы поставили `!important` один раз, единственный способ его перебить в будущем — поставить ещё один `!important`, ещё специфичнее. Это гонка вооружений, в которой через месяц никто не помнит, зачем на кнопке стоят три `!important` подряд. 

Правильный путь — разобраться в специфичности и написать селектор с нужным приоритетом, а не глушить проблему силой.

## ==Практический смысл==

- <font color="#ff0000"><b>Поддерживаемость проекта</b></font>. Внешний CSS-файл значит, что дизайн сайта можно поменять в одном месте, не трогая HTML ни на одной странице.
- <font color="#ff0000"><b>Предсказуемость стилей</b></font>. Понимание специфичности избавляет от ситуации «я меняю цвет, а он не меняется — почему?!». Вы будете точно знать, какое правило и почему победило.
- <font color="#ff0000"><b>Чтение чужого кода</b></font>. Открыв CSS другого разработчика, вы сразу поймёте логику селекторов, а не будете гадать, что к чему относится.
- <font color="#ff0000"><b>Отладка в DevTools</b></font>. На воркшопе по инструментам разработчика вы увидите специфичность буквально — браузер зачёркивает проигравшие правила прямо в интерфейсе.

## ==Типичные ошибки студентов==

1. **Использование ID для стилизации групп элементов.** ID уникален — если карточек товаров десять, им всем нужен класс, а не десять разных ID.
2. **Вера в то «что ниже в файле, то и побеждает».** Это работает только при равной специфичности — сначала считаются баллы.
3. **`!important` при первом же конфликте стилей.** Вместо этого необходимо посчитать специфичность и поправить селектор.
4. **Инлайн-стили «на скорую руку».** Кажется быстрым решением, но потом такой стиль невозможно перебить без ещё большего `!important`.
5. **Путаница между пробелом и `>` в комбинированных селекторах.** `nav a` — потомок на любой глубине, `nav > a` — только прямой ребёнок.

## ==Итог==

Сегодня вы заложили фундамент всего курса:

- CSS подключается тремя способами, но в проектах мы используем **внешний файл**;
- CSS-правило = **селектор + свойство + значение**;
- селекторы бывают базовые (тег, класс, ID) и комбинированные (потомок, прямой ребёнок, сосед);
- при конфликте стилей побеждает **специфичность** — сумма баллов селектора, а не порядок в файле;
- при равной специфичности побеждает то, что **написано ниже**;
- `!important` — это не решение проблемы специфичности, а её отложенное усложнение.

## ==Сквозной проект==

Начинаем стилизацию — сегодня работаем с **Визиткой** (`index.html` из HTML-курса).

### <mark style="background:rgba(240, 200, 0, 0.2)">Задание 1. Подключение стилей</mark>

Создайте файл `style.css` рядом с `index.html`, подключите его через `<link>` в `<head>`. Проверьте подключение: временно напишите `body { background: red; }` — если фон стал красным, всё работает, после проверки уберите.

### <mark style="background:rgba(240, 200, 0, 0.2)">Задание 2. Базовые стили</mark>

Задайте для `body` базовый шрифт (`font-family`) и цвет текста (`color`). Добавьте класс `.highlight` и повесьте его на своё имя или заголовок — задайте для класса другой цвет, отличный от общего цвета текста.

### <mark style="background:rgba(240, 200, 0, 0.2)">Задание 3. Найди ошибки</mark>

Объясните, какого цвета будет текст в каждом случае, и почему:

```css
p { color: blue; }
.text { color: green; }
#intro { color: purple; }
```

```html
<p id="intro" class="text">Привет, мир!</p>
```

<details open><summary><b>Ответы для проверки</b></summary> <p>Текст будет <font color="#ff0000">фиолетовым (purple)</font>. Считаем баллы: <font color="#ff0000">p</font> — тег, 1 балл; <font color="#ff0000">.text</font> — класс, 10 баллов; <font color="#ff0000">#intro</font> — ID, 100 баллов. Побеждает правило с наибольшей специфичностью — это ID, независимо от порядка в файле.</p> </details>

## ==Домашняя работа==

Изучите открытые источники, чтобы закрепить и расширить знания по теме:

- на [MDN](https://developer.mozilla.org/ru/docs/Web/CSS/CSS_selectors/Selector_structure) посмотрите полный список псевдоклассов — выберите 2–3, которые кажутся полезными для вашей Визитки;
- попробуйте специальный калькулятор специфичности (поищите «[CSS specificity calculator](https://polypane.app/css-specificity-calculator/)») — подставьте туда 3–4 своих селектора и проверьте, правильно ли вы посчитали баллы вручную;
- добавьте в `style.css` ещё 3–4 правила для разных элементов Визитки, используя как минимум один комбинированный селектор (потомок или прямой ребёнок).

> [!info] 
> На следующем занятии — блочная модель (**Box Model**): разберём content, padding, border и margin, а также почему `box-sizing: border-box` почти всегда должен стоять в самом начале вашего CSS-файла.
