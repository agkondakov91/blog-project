## ==Цели занятия==

До сих пор мы строили структуру страниц, опираясь только на разметку и html-теги. Мы строили визитку, галерею, FAQ-аккордеон. Всё это уже работает и логично размечено, но выглядит как черновик: браузерный шрифт, чёрный текст на белом фоне, никакого визуального ритма.

> [!tip]
Сегодня мы начинаем **стилизовать** то, что уже построено. 

Вы научитесь:

- **подключать** `CSS` к HTML-странице,
- **писать** правило по схеме «селектор → свойство → значение»,
- **выбирать** элементы для стилизации разными способами,
- **предсказывать**, какое правило победит, если два стиля конфликтуют.

Последний пункт — самый важный. Это тема, где новички обычно начинают судорожно расставлять **`!important`**, вместо того чтобы понимать, _почему_ браузер выбрал именно этот стиль. Сегодня мы во всём разберёмся, и сделаем так, чтобы `!important` вам не понадобился.

---
## ==Введение==

Если `HTML` отвечает на вопрос «**что это?**» — заголовок, список, картинка, то CSS отвечает на другой вопрос — «**как это должно выглядеть?**».

Представьте, что HTML — это здание из кирпичей: стены на месте, комнаты подписаны, всё стоит и не падает. А CSS — это дизайнер интерьера, который приходит и решает: какого цвета будут стены, какой формы будут окна, где повесить шторы.

> [!warning] Важно
>  HTML и CSS это **два разных языка с разными задачами**. Не пытайтесь через HTML-теги решать вопросы внешнего вида — для этого целиком существует CSS.

## ==Часть 1. Как подключить CSS к странице==

🔖 [Как подключить CSS к HTML](https://thecode.media/kak-podklyuchit-css-k-html/)

Есть три способа связать CSS с HTML — но реально используется в основном один.

### Внешний файл (external)

Стили выносятся в отдельный файл `style.css` и подключаются через тег `<link>` внутри `<head>` в файле HTML:

```html
<!-- index.html -->
<head>
  <link rel="stylesheet" href="style.css">
</head>
```

```css
/* styles.css */
body {
  color: #333;
}
```

> [!info] Почему именно так 
> Один файл `style.css` можно подключить к десяткам HTML-страниц сразу. Поменяли цвет фона в одном месте — обновились все страницы сайта. 

Это и есть главная сила CSS: разделение структуры и оформления.

### Внутренний блок (internal)

Можно писать стили прямо в `<head>` внутри тега `<style>`:

```html
<head>
  <style>
    body {
      color: #333;
    }
  </style>
</head>
```

> [!info] Работает только для одной этой страницы 
> В других HTML-файлах эти стили не появятся.

### Инлайн-стиль (inline)

Стиль пишется прямо в атрибуте `style` у конкретного тега:

```html
<p style="color: #333;">Текст</p>
```

> [!warning] Инлайн-стили — почти всегда плохая идея 
> Они смешивают структуру и оформление обратно в одном месте — то, от чего мы уходили. Кроме того, как вы увидите дальше, инлайн-стиль обладает огромной специфичностью и перебивает почти всё остальное, а это усложняет отладку. 

Используйте их только в исключительных случаях (например, стиль генерируется на лету через JavaScript).

**В курсе мы работаем только с внешним файлом** — заведите `styles.css` рядом с вашими HTML-файлами прямо сейчас.

## ==Часть 2. Анатомия CSS-правила==

🔖 [Основы CSS](https://developer.mozilla.org/ru/docs/Learn_web_development/Getting_started/Your_first_website/Styling_the_content)

CSS состоит из правил, которые указывают браузеру, как стилизовать элементы. Каждое правило — это инструкция, например: «***Сделайте все заголовки синими***».

Любое CSS-правило состоит из трёх частей:

```css
selector {
  property: value;
}
```

- **селектор** — _к кому_ обращаемся (какой элемент стилизуем),
- **свойство** — _что именно_ меняем (цвет, размер, отступ...),
- **значение** — _каким_ делаем это свойство.

```css
p {
  color: red;
  font-size: 12px;
}
```

Здесь мы говорим браузеру: «у всех `<p>` на странице сделай текст красным, а размер шрифта — 12 пикселей».

> [!tip] Читайте CSS-правило как предложение
> «Для параграфа: цвет — красный; размер шрифта — 12 пикселей». Если вы можете так прочитать код вслух — вы его понимаете.

Свойств, которые можно стилизовать, достаточно много. Не нужно сразу их все запоминать. Мы будем сталкиваться с основными свойствами по ходу курса, а некоторые будем искать в документации. 

Однако, для саморазвития, полезно посмотреть с чем вам придётся работать в будущем.

🔖 https://developer.mozilla.org/ru/docs/Web/CSS/Reference

## ==Часть 3. Селекторы: как выбрать нужный элемент==

🔖 [CSS Diner - игра для изучения CSS](https://flukeout.github.io/)

Для того, чтобы можно было выбрать любой **html-элемент** на странице в CSS предусмотрены селекторы. Посмотрим на базовые селекторы.

### Базовые селекторы

|Селектор|Что выбирает|Пример|
|---|---|---|
|Тег|Все элементы этого тега|`p { }` — все параграфы|
|Класс|Элементы с этим классом|`.card { }` — все с `class="card"`|
|ID|Один конкретный элемент|`#header { }` — элемент с `id="header"`|
|Универсальный|Вообще всё на странице|`* { }`|

Например, у нас есть такая разметка:

```html
<body id="main">
    <article class="card">
        <div class="card-image"></div>
        <h2 class="card-title">Heading</h2>
        <p class="card-subtitle">
	        A brief description of the current product card will appear here
	    </p>
        <button>Action</button>
    </article>
</body>
```

```css
button {
	background-color: #FFAA00;
	border: none;
    border-radius: 10px;
}

#main {
	margin: 0 auto;
	background-color: #333;
}

.card {
	padding: 12px;
	width: 280px;
	background-color: white;
	border-radius: 10px;
}
```

> [!info] Класс vs ID
> Класс (`.card`) можно вешать на сколько угодно элементов — это как бейджик «я такой-то». ID (`#main`) должен быть **уникальным** на странице — как паспорт, только один владелец.

Если вы стилизуете группу похожих элементов (карточки товаров, кнопки) — почти всегда нужен класс, а не ID.

### Комбинированные селекторы

Селекторы можно сочетать, чтобы точнее указать, что необходимо стилизовать:

```css
/* Все теги p внутри тега article */
article p {
    color: red;
}

/* Прямые дети main (не внуки) */
main > section {
	margin-bottom: 20px;
}

/* Элемент сразу после header */
header + main {
	padding-top: 40px;
}

/* Несколько классов через запятую — общее правило сразу для всех */
h1, h2, h3 {
	font-family: sans-serif;
}
```

- `nav a` — пробел означает «где угодно внутри», на любой глубине вложенности;
- `main > section` — знак `>` означает «только прямой ребёнок», не дочерний;
- `header + main` — знак `+` означает «сосед сразу после».

### Псевдоклассы: состояния элемента

Псевдокласс описывает **состояние** элемента, а не его тип или класс:

```css
/* при наведении курсора */
button:hover {
    color: #FFAA00;
    background-color: #2e2e2e;
    cursor: pointer;
}

/* когда поле в фокусе */
button:focus {
    outline: 2px solid #2e2e2e;
}

/* первый элемент в списке */
li:first-child {
	font-weight: bold;
}
```

Мы вернёмся к псевдоклассам подробнее, когда дойдём до интерактивных элементов — а пока достаточно знать, что двоеточие `:` в селекторе значит «в каком-то состоянии», а не «часть имени».

## ==Часть 4. Специфичность: кто победит при конфликте==

🔖 [CSS Специфичность](https://developer.mozilla.org/ru/docs/Web/CSS/Guides/Cascade/Specificity)

Что если два правила указывают на один и тот же элемент, но с разными значениями? Например, у нас есть такая разметка **html**:

```html
<p class="intro">Какого цвета будет этот текст?</p>
```

В **css**, при этом, указаны такие стили:

```css
p { color: blue; }
.intro { color: green; }
```

> [!tip] Вопрос
> Какой цвет в итоге применится к элементу? Ответ: **зелёный**.

 Не потому что `.intro` написан позже в файле, а потому что у **класса приоритет выше**, чем у тега. Это и есть специфичность — система баллов, по которой браузер решает, чьё правило важнее.

### Как считаются баллы

Специфичность выражается в виде четырёх чисел (0, 0, 0, 0), где каждое соответствует определённому типу селектора:

| Тип селектора               | Баллы                                          | Пример               |
| --------------------------- | ---------------------------------------------- | -------------------- |
| Инлайн-стиль                | 1, 0, 0, 0 = <font color="#ff0000">1000</font> | `style="color: red"` |
| ID                          | 0, 1, 0, 0 = <font color="#ff0000">100</font>  | `#header`            |
| Класс, псевдокласс, атрибут | 0, 0, 1, 0 = <font color="#ff0000">10</font>   | `.card`, `:hover`    |
| Тег                         | 0, 0, 0, 1 = <font color="#ff0000">1</font>    | `p`, `h1`            |

Баллы за все части селектора **складываются**. Например, `nav .active a` — это класс (10) + два тега (2) = **12 баллов**.

> [!warning] Частая ошибка
> Думать, что побеждает правило, которое ниже в файле. 

Порядок в файле побеждает **только при равной специфичности**. Если у одного правила 10 баллов, а у другого 1 — выиграет то, что с 10 баллами, даже если оно написано раньше.

### А если специфичность одинаковая?

Вот тут действительно работает порядок в файле — побеждает то правило, которое **написано ниже**:

```css
.button { background: gray; }
.button { background: navy; } /* это правило победит — оно ниже */
```

### !important

Для любого свойства можно указать ключевое слово `!important`:

```css
p { color: blue !important; }
```

`!important` перебивает вообще всё, кроме другого `!important` с ещё бо́льшим приоритетом. Звучит как удобная кнопка «сделать по-моему», но у неё есть цена:

> [!warning] Проблема !important 
> Как только вы поставили `!important` один раз, единственный способ его перебить в будущем — поставить ещё один `!important`, ещё специфичнее. 

Это гонка вооружений, в которой через месяц никто не помнит, зачем на кнопке стоят три `!important` подряд. 

> [!info] Правильный путь
> Разобраться в специфичности и написать селектор с нужным приоритетом, а не глушить проблему силой.

## ==Итог==

Сегодня вы заложили фундамент всего курса:

- CSS подключается тремя способами, но в проектах мы используем **внешний файл**;
- CSS-правило = **селектор + свойство + значение**;
- селекторы бывают базовые (тег, класс, ID) и комбинированные (потомок, прямой ребёнок, сосед);
- при конфликте стилей побеждает **специфичность** — сумма баллов селектора;
- при равной специфичности побеждает то правило, что **написано ниже**;
- `!important` — это не решение проблемы специфичности, а её отложенное усложнение.
