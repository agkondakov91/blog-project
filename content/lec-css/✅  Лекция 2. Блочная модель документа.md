## ==Цели занятия==

На прошлом занятии вы научились _выбирать_ элементы и задавать им цвет и шрифт. Но как только доходит до размеров и отступов, у новичков начинается магия: «я задал `width: 300px`, а элемент занял 340 — откуда лишние 40 пикселей?».

Сегодня эта магия закончится. Вы научитесь:

- видеть **любой элемент как коробку** из четырёх слоёв,
- различать **padding** (внутренний отступ) и **margin** (внешний),
- понимать, почему два вертикальных `margin` **схлопываются** в один,
- включать **`box-sizing: border-box`** — одну строчку, которая делает размеры логичными.

Это фундамент всех гибких раскладок: Flexbox и Grid, которые пойдут дальше, расставляют по экрану именно эти «коробки». Не поняв коробку — не поймёшь раскладку.

---
## ==Введение==

Откройте любую страницу и мысленно обведите каждый элемент прямоугольником. Заголовок — прямоугольник. Абзац — прямоугольник. Картинка — прямоугольник. Даже одно слово внутри строки — прямоугольник.

Это не метафора, а буквальное устройство браузера: <font color="#ff0000"><b>каждый элемент на странице — это прямоугольная коробка</b></font>. И у этой коробки есть четыре слоя, вложенных друг в друга, как матрёшка.

> [!tip] 
> Когда вы поймёте эти четыре слоя, вы перестанете «подбирать» отступы наугад и начнёте их **осознанно проектировать**. Это один из тех моментов, после которого CSS резко перестаёт казаться хаосом.

## ==Часть 1. Четыре слоя коробки==

🔖 [Блочная модель CSS](https://developer.mozilla.org/ru/docs/Learn_web_development/Core/Styling_basics/Box_model)

Чтобы разобраться в блочной модели необходимо взглянуть на её представление в вебе. Это достаточно распространённая картинка, которую рисует сам браузер. 

Откройте любой сайт, перейдите в режим разработчика (кнопка F12), выберете вкладку **Elements -> Styles** и прокрутите стили в самый конец.
![[css_01.png]]

Вот она, наша коробка! И изнутри наружу она состоит из:

- **content** — само содержимое: текст, картинка. Его размер задаётся через `width` и `height`.
- **padding** — внутренний отступ между содержимым и рамкой. Как поля внутри рамки для картины.
- **border** — рамка вокруг содержимого и padding.
- **margin** — внешний отступ, расстояние **до соседних элементов**. Воздух вокруг коробки.

```css
.card {
  width: 300px;            /* ширина content */
  padding: 20px;           /* внутренний отступ со всех сторон */
  border: 2px solid gray;  /* рамка */
  margin: 16px;            /* внешний отступ до соседей */
}
```

> [!info] Как запомнить разницу padding и margin 
> **padding** — пространство _внутри_ коробки, которое отодвигает содержимое от краёв. Если задать коробке фон, padding **будет закрашен** этим фоном. 
> **margin** — пространство _снаружи_ коробки, которое отодвигает её от соседей. Это пространство **всегда прозрачное**, фоном не закрашивается.

Простой вопрос для проверки: «мне нужен воздух _внутри_ элемента или _между_ элементами?»

## ==Часть 2. Как задавать отступы с разных сторон==

🔖 [Правила организации отступов](https://skillbox.ru/media/code/pravila_organizatsii_otstupov_kak_sdelat_vyerstku_gibkoy_i_ne_dopustit_oshibok/)

И `padding`, и `margin` можно задавать для каждой стороны отдельно или сокращённо.

### <mark style="background:rgba(240, 200, 0, 0.2)">Отдельно по сторонам</mark>

```css
.box {
  margin-top: 10px;
  margin-right: 20px;
  margin-bottom: 10px;
  margin-left: 20px;
}
```

### <mark style="background:rgba(240, 200, 0, 0.2)">Сокращённая запись</mark>

```css
.box { margin: 10px 20px 10px 20px; }  /* top right bottom left — по часовой стрелке */
.box { margin: 10px 20px; }            /* верх/низ = 10px, лево/право = 20px */
.box { margin: 10px; }                 /* все четыре стороны = 10px */
```

> [!tip] Правило часовой стрелки 
> Когда пишете четыре значения — читайте их по часовой стрелке, начиная сверху: **top → right → bottom → left**. Мнемоника: **T**op **R**ight **B**ottom **L**eft — «TRouBLe». Не помните порядок — задавайте стороны по отдельности, это не ошибка.

## ==Часть 3. Схлопывание margin (margin collapse)==

🔖 [Схлопывание отступов](https://developer.mozilla.org/ru/docs/Web/CSS/Guides/Box_model/Margin_collapsing)

Вот эффект, который стабильно ставит новичков в тупик. Два вертикальных `margin`, стоящих друг напротив друга, **не складываются, а схлопываются** — остаётся только больший из двух.

```html
<p>Первый абзац</p>
<p>Второй абзац</p>
```

```css
p {
  margin-top: 30px;
  margin-bottom: 20px;
}
```

Логично ожидать между абзацами `20px + 30px = 50px`. Но реальный отступ будет **30px** — берётся больший из двух, меньший «схлопывается».

> [!warning] Схлопывание работает только по вертикали 
> Горизонтальные `margin` (left/right) **никогда** не схлопываются — они всегда складываются. Схлопываются только верхний и нижний между соседними блоками.

Это одна из главных причин, почему отступы «не сходятся» в арифметике новичка.

> [!info] Практический вывод
> Из-за схлопывания многие разработчики договариваются задавать отступы **только с одной стороны** — например, всегда `margin-bottom`, никогда `margin-top`.

Тогда схлопывать нечему, и арифметика становится предсказуемой. Хорошая привычка на будущее.

## ==Часть 4. box-sizing: главная строчка вашего CSS==

🔖 [box-sizing](https://developer.mozilla.org/ru/docs/Web/CSS/Reference/Properties/box-sizing)

А теперь — обещанное объяснение «лишних пикселей».

### <mark style="background:rgba(240, 200, 0, 0.2)">Поведение по умолчанию (content-box)</mark>

По умолчанию `width` задаёт ширину **только для блока content**. А padding и border **добавляются сверху**:

```css
.card {
  width: 300px;
  padding: 20px;
  border: 2px solid;
}
```

Реальная ширина на экране: `300 + 20 + 20 + 2 + 2 = 344px`. Те самые «лишние» пиксели, которые ломают раскладку.

Так происходит, потому что по умолчанию для всех элементов применяется свойство:

```css
box-sizing: content-box;
```

> [!warning] Почему это неудобно 
> Вы говорите «хочу карточку шириной 300px», а получаете 344px. Чтобы получить ровно 300, приходится вычитать padding и border вручную: `width: 256px`. И пересчитывать каждый раз при изменении отступов. 

Это утомительно и приводит к ошибкам.

### <mark style="background:rgba(240, 200, 0, 0.2)">Решение — border-box</mark>

Для решения данной проблемы возьмите себе за правило всегда использовать свойство:

```css
.card {
  box-sizing: border-box;
  width: 300px;
  padding: 20px;
  border: 2px solid;
}
```

Теперь `width: 300px` — это **вся коробка целиком**, включая padding и border. Содержимое просто ужимается, чтобы всё уместилось в 300px. Сказали 300 — получили 300.

### <mark style="background:rgba(240, 200, 0, 0.2)">Как включить это для всего проекта</mark>

Почти все современные проекты ставят это правило в самое начало CSS-файла:

```css
* {
  box-sizing: border-box;
}
```

Универсальный селектор `*` (помните из прошлой лекции?) применяет `border-box` ко всем элементам сразу. Написали один раз — забыли про «лишние пиксели» навсегда.

> [!tip] 
> Это настолько стандартная практика, что многие считают `content-box` по умолчанию исторической ошибкой CSS. Заведите привычку начинать любой `style.css` с этого правила — как программист начинает файл с импортов.

## ==Практический смысл==

- <font color="#ff0000"><b>Предсказуемые размеры</b></font>. С `border-box` заданная ширина — это реальная ширина на экране. Никакой ручной арифметики с вычитанием отступов.
- <font color="#ff0000"><b>Ровные раскладки</b></font>. Когда все элементы честно занимают заявленную ширину, они складываются в аккуратную сетку без переносов и «уезжающих» блоков.
- <font color="#ff0000"><b>Осознанные отступы</b></font>. Понимание padding vs margin избавляет от подбора наугад: вы сразу знаете, внутренний вам нужен отступ или внешний.
- <font color="#ff0000"><b>Отладка в DevTools</b></font>. На воркшопе по инструментам вы увидите эту коробку буквально — браузер рисует content, padding, border и margin разными цветами при наведении на элемент.

## ==Типичные ошибки студентов==

1. **Путают padding и margin.** Нужен воздух _внутри_ элемента (например, текст жмётся к рамке) — это padding. Нужно расстояние _между_ элементами — это margin.
2. **Забывают про box-sizing и воюют с «лишними» пикселями.** Задают `width`, удивляются реальному размеру, начинают вычитать padding вручную вместо одной строчки `border-box`.
3. **Ждут сложения вертикальных margin.** `margin-bottom: 20px` + `margin-top: 30px` дают не 50, а 30 — схлопывание.
4. **Задают margin с обеих вертикальных сторон и путаются в отступах.** Проще договориться про одну сторону (обычно `margin-bottom`).
5. **Пытаются задать margin строчным элементам** (`<span>`, `<a>`) по вертикали — у строчных элементов вертикальный margin не работает так, как ожидается. Но это тема будущих занятий про `display`.

## ==Итог==

Сегодня вы разобрали, из чего состоит любой элемент на странице:

- каждый элемент — это **коробка** из четырёх слоёв: content → padding → border → margin;
- **padding** — внутренний отступ (закрашивается фоном), **margin** — внешний (всегда прозрачный);
- отступы задаются по сторонам или сокращённо по часовой стрелке (Top Right Bottom Left);
- вертикальные margin соседей **схлопываются** — берётся больший, а не сумма;
- `box-sizing: border-box` делает `width` реальной шириной всей коробки — ставьте его через `* { }` в начале каждого проекта.

## ==Сквозной проект==

Продолжаем стилизацию **Визитки** — превращаем «сырой» текст в аккуратную карточку.

### <mark style="background:rgba(240, 200, 0, 0.2)">Задание 1. Глобальный border-box</mark>

В начало `style.css` добавьте правило `* { box-sizing: border-box; }`. Это ваша новая обязательная первая строчка в любом проекте.

### <mark style="background:rgba(240, 200, 0, 0.2)">Задание 2. Карточка с отступами</mark>

Оберните содержимое Визитки в элемент с классом `.card` (если его ещё нет) и задайте ему: фиксированную `width`, внутренний `padding`, рамку `border` и внешний `margin` для центрирования или отступа от краёв. Убедитесь, что `padding` закрашивается, если задать карточке `background`.

### <mark style="background:rgba(240, 200, 0, 0.2)">Задание 3. Найди ошибки</mark>

Студент хочет карточку **ровно 400px шириной** с отступами внутри, но она получается шире. Найдите причину и исправьте:

```css
.card {
  width: 400px;
  padding: 30px;
  border: 5px solid navy;
}
```

<details open><summary><b>Ответы для проверки</b></summary> <p>Реальная ширина карточки: <font color="#ff0000">400 + 30 + 30 + 5 + 5 = 470px</font>, потому что по умолчанию действует <font color="#ff0000">content-box</font> и padding с border добавляются к width.</p> <p>Исправление — добавить <font color="#ff0000">box-sizing: border-box;</font>. Тогда width: 400px станет шириной всей коробки, и карточка займёт ровно 400px.</p> </details>

## ==Домашняя работа==

Изучите открытые источники, чтобы закрепить и расширить знания по теме:

- на [MDN](https://developer.mozilla.org/ru/docs/Web/CSS/CSS_box_model/Introduction_to_the_CSS_box_model) прочитайте введение в блочную модель — обратите внимание на разницу поведения `block` и `inline` элементов в контексте коробки;
- откройте инструменты разработчика (F12), наведитесь на любой элемент своей Визитки и найдите вкладку с визуализацией коробки — рассмотрите, как браузер подсвечивает content, padding, border и margin разными цветами;
- поэкспериментируйте: временно переключите `box-sizing` между `content-box` и `border-box` на своей карточке и посмотрите, как меняется её реальная ширина.

> [!info] 
> На следующем занятии — единицы измерения и современный цвет: разберём, чем `rem` лучше `px` для шрифтов, что такое `vh`/`dvh` и почему на мобильных они разные, а также познакомимся с цветовой моделью `oklch` и функцией `light-dark()` для тёмной темы.
